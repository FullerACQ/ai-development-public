## Snapshot provenance

[License sources](licenses/SOURCES.md) records the public revisions used to obtain
the license texts, their SHA-256 checksums, and the Archify blob comparisons.
These license-source revisions do not assert that every copied skill is an exact
checkout of the same revision.

`skill-lock.json` records only retained skills and their public repository
origins. Installation timestamps and old `skillFolderHash` values were omitted:
this curated snapshot is not the original installer state, and some supporting
metadata was excluded. No historical folder hash is presented as a hash of the
current folders.

`v3.0.1` checkout. Of those files, 302 match that release at their original paths.
The other 13 match blobs accessible in the same public upstream repository; their
paths and blob IDs are recorded in [License sources](licenses/SOURCES.md).

`assets/JetBrainsMono-OFL.txt` remain intact. The release's MIT copyright and
permission notice names tt-a1i and Cocoon AI. Upstream later adopted Apache-2.0
while explicitly preserving historical MIT grants. Both license texts and the
actual transition NOTICE are bundled; do not infer a blanket MIT grant for every
future upstream change from the retained historical file.

## Helper references and host requirements

Required packaged Markdown reference files and Archify runtime imports are
present. Example links inside the fenced templates in `grill-with-docs` and
`write-a-skill` describe files a future project would create; they are not missing
packaged helpers.

Some skills operate on an external project or require installed tools:

- Paperclip developer, plugin, diagnosis, and benchmark workflows expect the
  corresponding Paperclip source checkout, project documents, CLI, or benchmark
  scripts. Those host-project files are not part of a skill installation.
- Graphify requires its separately installed `graphifyy` runtime. Visual Plan
  requires the Agent-Native CLI or its MCP connector.
- Pulumi, Kubernetes, GitOps, monitoring, and CI examples require their stated
  platform tools and credentials supplied locally by the user.
- Archify's packaged CLI and five renderer modes are self-contained. Its upstream
  maintainer npm scripts and some repository tests refer to sibling `scripts/`,
  `.agents/`, and website/docs files in the full Archify repository. The full
  upstream `npm test`/website build is not a standalone skill-slice command.
  Use the full upstream checkout for those maintainer tasks.

The old Archify `test/fixtures/fail-migration-cleanup.mjs` release fixture is absent
from the copied current tree. The current migration test constructs that helper
in its temporary directory, so no replacement fixture is required.

## Review scope

The retained current files were scanned for private organization domains,
service names, employee identity, real cloud account identifiers, credentials,
and symlinks. No private organization residual or live credential was identified.
Credential-shaped upstream examples were replaced with explicit placeholders.
Public vendor/sample identifiers and generic product terminology are not private
organization identifiers.

Private or ownership-uncertain skills, external symlinks, `.claude` configuration,
`.DS_Store`, `node_modules`, and `dist` were excluded from the copied slice. This
review covers this skills/license slice, not unrelated repository components or
any future installation changes.
